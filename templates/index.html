Project Context

Understanding In-Play T20 Win Probability

Predicting match outcomes during an IPL run chase requires dynamic feature modeling that balances required scoring velocity against resource depletion.

The T20 Chase Challenge

The Indian Premier League (IPL) is among the most volatile sports leagues in the world, where match momentum shifts rapidly over-by-over. In a 2nd innings run-chase, every boundary scored raises the batting team's probability, while every fallen wicket drastically depletes their remaining batting depth.

This project develops an end-to-end Machine Learning pipeline that maps dynamic match state variables—including runs required, balls remaining, wickets in hand, and required run rate (RRR)—into smooth, calibrated winning probabilities.

Problem Statement

Conventional cricket statistics (such as static head-to-head records or simple run-rate comparisons) fail to encapsulate the dynamic pressure of T20 death overs and venue dew factors.

Furthermore, uncalibrated tree-based models often generate abrupt, erratic probability jumps that lack real-world match realism. The goal of this system is to formulate a continuous, statistically sound machine learning framework that delivers dependable live winning probabilities and provides sports analysts, coaches, and fans with intuitive visual insights.

Pipeline & Workflow

Machine Learning System Architecture

From raw historical ball-by-ball match situations to interactive probability inference.

01
Data Preprocessing

Historical IPL matches are filtered for 2nd innings run chases. Data cleaning removes invalid records, no-results, rain-truncated DLS matches, and handles stadium aliases across 16 seasons.

02
Feature Engineering

Five high-impact dynamic features are computed: Runs Left, Balls Left, Wickets in Hand, Current Run Rate (CRR = Score × 6 / Balls), and Required Run Rate (RRR = Runs Left × 6 / Balls Left).

03
Scikit-Learn Pipeline

A ColumnTransformer encodes categorical variables (Batting Team, Bowling Team, City) via One-Hot Encoding and feeds numerical match features directly into the Logistic Regression classifier.

04
Calibrated Probability

Logistic Regression produces smooth, well-calibrated probabilities via the Sigmoid curve σ(wTx + b), preventing erratic jumps and honoring cricket chase dynamics monotonically.

05
Flask RESTful Engine

The trained model is serialized to model.pkl and loaded into Flask memory. A REST API handles live POST requests with rigorous input boundary validation and < 20ms response time.

06
Chart.js Visualization

Frontend dynamically renders interactive win percentage donuts, dual team progress bars, pressure indicators, and match diagnostics powered by Chart.js and Bootstrap 5.

Comprehensive Report

Project Documentation

Academic-standard documentation covering methodology, dataset structure, equations, and experimental results.

The Indian Premier League is the world's preeminent Twenty20 cricket tournament. Unlike test matches or 50-over ODIs, T20 cricket compresses match tempo into 120 legal deliveries per innings. During the second innings (the chase), victory is strictly binary: the chasing team must score strictly more runs than the defending team within 120 balls without losing all 10 wickets. Interactive in-play win probability estimation provides viewers, broadcasters, and analytics teams with data-driven evaluations of which side controls match momentum.

The state of an in-progress IPL run-chase is formally parameterized by nine orthogonal features:

  • Runs Left: \( R_{\text{left}} = \text{Target} - \text{Current Score} \)
  • Balls Left: \( B_{\text{left}} = 120 - [(\lfloor\text{Overs}\rfloor \times 6) + \text{Balls in Over}] \)
  • Wickets in Hand: \( W_{\text{rem}} = 10 - \text{Wickets Fallen} \)
  • Current Run Rate (CRR): \( \text{CRR} = \frac{\text{Current Score} \times 6}{120 - B_{\text{left}}} \)
  • Required Run Rate (RRR): \( \text{RRR} = \frac{R_{\text{left}} \times 6}{B_{\text{left}}} \)
  • Categorical Context: \( \text{Batting Team}, \text{Bowling Team}, \text{Host City} \)

Winning probability is computed via the logistic sigmoid function:
\( P(Y = 1 \mid \mathbf{x}) = \frac{1}{1 + e^{-(\mathbf{w}^T \mathbf{x} + b)}} \)
Where \( Y = 1 \) denotes chasing team victory and \( Y = 0 \) denotes defending team victory.

The model is trained on dataset/matches.csv, comprising 22,000+ match situation snapshots spanning 1,200 simulated and historical IPL fixtures. Preprocessing steps include:
  1. Dropping matches decided by Duckworth-Lewis-Stern (DLS) method or abandoned due to weather.
  2. Harmonizing legacy franchise names (e.g. Delhi Daredevils to Delhi Capitals, Kings XI Punjab to Punjab Kings).
  3. Filtering out impossible states (e.g. Current Score ≥ Target, Balls Left = 0, or Wickets Fallen = 10).
  4. Splitting data using an 80:20 stratified train-test split to preserve natural chase-win ratios.
